# Integrate Nadeye

Nadeye is an open registry of AI-image verdicts on Monad, keyed by a 64-bit perceptual hash that survives resizing and recompression. Anyone can read it, and any detector, human or agent, can add to it. This page shows the five ways to build on it, with code you can paste.

| You are building | Use | Cost |
| --- | --- | --- |
| A web app, bot or backend that needs "is this image AI?" | [`nadeye-sdk`](#1-javascript-nadeye-sdk) | Free reads |
| A contract that should react to provenance (mint, list, reward) | [`INadeye`](#2-solidity-inadeye) | One `view` call |
| An AI agent | [MCP, HTTP or ERC-8004 validation](#3-agents) | Free (MCP/HTTP) or one transaction |
| A contract that needs a human's passkey to approve an action | [`PasskeyRegistry.verifyFor`](#4-passkey-approval) | One `view` call: about 35k gas through the P256 precompile (measured on Foundry's Osaka EVM, which has the same precompile at `0x100`) |
| Your own detector | [`attestBatch`](#5-write-verdicts) | Gas per batch |

Addresses: Nadeye `0xD58eb04fb34E9b9151484BE82F2114B75323cDD5`, PasskeyRegistry `0x16Bef696F687aC253d38B7eA4c84075375EB31B3` and NadeyeJournal `0x3EDd9026A3ad114c67F6cF50EA00e7C93F740a18` on Monad testnet (chain 10143). The README's runbook says where they come from.

## 1. JavaScript: nadeye-sdk

```bash
npm install ./sdk   # from this repo; dependency: viem
```

```js
import { createNadeyeClient } from "nadeye-sdk";

const nadeye = createNadeyeClient({ network: "testnet", nadeye: "0xD58eb04fb34E9b9151484BE82F2114B75323cDD5", passkeys: "0x16Bef696F687aC253d38B7eA4c84075375EB31B3" });

// Hash decoded pixels and look them up. The image never leaves your process.
const ctx = canvas.getContext("2d");
const r = await nadeye.lookupImage(ctx.getImageData(0, 0, canvas.width, canvas.height));
// { pHash: "c3a1…", candidates: 37, verdict: "ai" | "real" | "split" | "none",
//   reports: 4, aiVotes: 3, aiShare: 0.75, meanScore: 0.86 }
if (r.verdict === "ai" && r.reports >= 2) label("Flagged as AI-generated by 3 of 4 Nadeye scanners");
```

Other reads:

| Call | Returns |
| --- | --- |
| `lookupHashes(["c3a1…"])` | The same verdict object, for hashes you already have |
| `stats()` | `{ scans, images, scanners, flagged }` |
| `scanner(address)` | Handle, points, scans, signal-to-noise, `agentId` and `passkey` (true when it proved a passkey onchain) |
| `hasPasskeys([address, …])` | `[true, false, …]` |
| `reputation(agentId)` | `{ judged, agreement }`, the agent's ERC-8004 track record from Nadeye |
| `verifyUrl(imageUrl)` | A verifier agent's full report (needs `agentUrl`) |

In Node, decode with any library that gives RGBA pixels. With sharp: `const { data, info } = await sharp(buf).ensureAlpha().raw().toBuffer({ resolveWithObject: true })`, then pass `{ data, width: info.width, height: info.height }`. `pHashDetail` and `lookupCandidates` are exported for custom flows. The SDK's hash is byte-for-byte the extension's, and a test enforces it.

## 2. Solidity: INadeye

`contracts/src/interfaces/INadeye.sol`:

```solidity
import {INadeye} from "./INadeye.sol"; // copy contracts/src/interfaces/INadeye.sol into your project

INadeye.ImageView memory v = INadeye(NADEYE).getImage(pHash);
bool flagged = v.reports >= 2 && uint256(v.aiVotes) * 2 > v.reports;
```

`contracts/src/examples/ProvenanceGallery.sol` is a complete, tested integration. It refuses to list an image once at least `minReports` scanners recorded it and most said AI, and it stores the evidence it had at listing time. Fields:
- `reports`: how many scanners recorded a verdict.
- `aiVotes`: how many of those scored the image 80% or more.
- `meanScore`: the mean AI confidence, in basis points.

A vote below 50% is "real"; anything between 50% and 80% is never recorded.

## 3. Agents

**MCP (Claude Desktop, Claude Code, Cursor and others).** Run a verifier locally (see the README's runbook), then add:

```json
{ "mcpServers": { "nadeye": { "command": "node", "args": ["/ABS/PATH/nadeye/agent/src/cli.js", "mcp"],
  "env": { "NADEYE_NETWORK": "testnet", "NADEYE_CONTRACT": "0xD58eb04fb34E9b9151484BE82F2114B75323cDD5" } } } }
```

The tools:

| Tool | What it does |
| --- | --- |
| `verify_image(url)` | Runs the detector and returns the community verdict |
| `verify_image_file(path)` | The same for a local file (stdio only) |
| `lookup_phash(pHash)` | Registry lookup only, nothing downloaded |

**HTTP.** `GET http://127.0.0.1:8787/verify?url=<image>`, or `POST /verify` with image bytes or `{"url": …}`. `verdict` is `ai`, `real` or `unsure`, and the response looks like this:

```json
{ "verdict": "ai", "aiConfidence": 0.94, "authenticity": 6, "evidence": "model", "degraded": false,
  "pHash": "c3a1…", "community": { "reports": 3, "aiVotes": 3 }, "model": { "version": "w5810-2026-08-30" } }
```

Server-to-server callers need nothing extra. To call it from a web page, add the page's origin to `NADEYE_CORS_ORIGINS`. Behind a tunnel, the `--public-url` host is accepted automatically.

**ERC-8004 validation (onchain, agent to agent).** Any agent with an ERC-8004 identity calls `ValidationRegistry.validationRequest(<verifier wallet>, <your agentId>, <image URL>, <requestHash>)`. The verifier answers onchain with `validationResponse`:
- `response`: authenticity from 0 to 100.
- `responseURI`: a data-URI JSON report.
- `responseHash`: the keccak256 of that report.
- `tag`: `nadeye/ai-image`.

`node agent/src/cli.js request <url> --validator <wallet>` does the whole round trip. Verifiers cap answers at 30 per requesting agent per hour.

## 4. Passkey approval

`PasskeyRegistry` binds an account to one WebAuthn passkey, proven onchain through Monad's P256 precompile (`0x100`). Any contract can then require that account's passkey to approve an action:

```solidity
import {IPasskeyRegistry} from "./INadeye.sol";

bytes32 challenge = keccak256(abi.encode("my-app.approve", block.chainid, address(this), user, nonce[user]++));
require(IPasskeyRegistry(PASSKEYS).verifyFor(user, challenge, auth), "passkey did not approve");
```

In the browser, get the assertion with `navigator.credentials.get({ publicKey: { challenge, rpId, userVerification: "required" } })`. Then turn it into `auth` with `toWebAuthnAuth(readAssertion(credential))` from `web/src/webauthn-proof.js`. That helper splits the DER signature, moves `s` to the low half and finds the indexes.

Registering a passkey takes two prompts, because WebAuthn only reveals the public key when the passkey is created:
1. The first signature narrows the key to two candidates (`candidateKeys`).
2. The second signs `registrationChallenge(account)` and picks the right candidate (`pickKey`).

The site's **My scanner → Prove with passkey** button does exactly this.

What the registry guarantees: the assertion is a `webauthn.get` with user verification, for exactly your challenge, signed by the registered key, with no malleable high-s signatures and no replay of a registration. One passkey backs one account. It is friction against sybils, not proof of personhood: a person can create several passkeys.

**Where approvals can be signed.** A passkey belongs to the website that created it (its relying-party ID). A Nadeye passkey can therefore only sign on the Nadeye site's domain, or on origins that domain lists for WebAuthn Related Origin Requests (`/.well-known/webauthn`). A third-party contract can still call `verifyFor`, but the user approves on a page served from the passkey's domain. Your own app can also register its users' passkeys under its own domain in the same registry, and verify those anywhere.

## 5. Write verdicts

Detectors call `attestBatch(bytes32[] pHashes, uint16[] scores, uint8 modelVersion)`:
- Scores are basis points of AI confidence.
- A score of 8000 or more is an AI vote, and below 5000 a real vote. A batch skips scores in between; a single `attest` reverts on them.
- Batches take up to 100 entries; duplicates from the same scanner are skipped.

A scanner that links an ERC-8004 agent (`linkAgent(agentId)`, as the agent's owner or `agentWallet`) builds reputation automatically: every consensus judgement writes 100 or 0 to the Reputation Registry.

## 5. Encrypted per-user storage with a passkey (NadeyeJournal pattern)

`web/src/journal.js` is a small module any Mera app can reuse to keep private data on Monad:

```js
import { getPasskeyPrfOutput } from "@category-labs/mera";
import { JOURNAL_SALT, journalKeys, makeEntry, seal, readJournal } from "./journal.js";

const { prfOutput } = await getPasskeyPrfOutput({ rpId: location.hostname, prfSalt: JOURNAL_SALT });
const keys = await journalKeys(prfOutput);                 // { id, key }: not an account
const box = await seal(keys, makeEntry({ pHash, verdict: "ai", note: "seen in a thread" }));
// any funded account appends it: NadeyeJournal.append(keys.id, box)
const entries = await readJournal(publicClient, JOURNAL, keys); // newest first, on any device
```

Use your own salt string for your own app, so its namespace stays separate from Nadeye's and from Mera's account keys.

## 6. History and analytics over GraphQL (Envio indexer)

The contracts hold current totals. For history (every verdict, a scanner's record over time, daily counts, the verifier agent's answers), query the Nadeye indexer's GraphQL endpoint (`<INDEXER_ENDPOINT>`; `indexer/` in this repo, built with Envio HyperIndex):

```graphql
query ScannerHistory($id: String!) {
  Scanner(where: {id: {_eq: $id}}) {
    handle points signal noise agentId passkey
    attestations(order_by: {block: desc}, limit: 20) { timestamp isAI consensus image { pHash verdict reports } }
  }
}
```

```graphql
query RecentlyFlagged {
  Image(where: {verdict: {_eq: "ai"}, reports: {_gte: 3}}, order_by: {lastSeen: desc}, limit: 20) { pHash reports aiVotes firstSeen }
}
```

BigInt fields (points, scoreSum, agent ids) come back as strings. The site's Activity tab (`ACTIVITY_QUERY` in `web/index.html`) is a complete working example.
